# شعبة الاستفسارات والشكاوى

مستودع تطوير نموذج أولي للوحة إدارة الاستفسارات والشكاوى، مع بناء تدريجي لخادم محلي وقاعدة بيانات SQLite.

## الحالة الحالية

- الواجهة الحالية ما زالت نموذجًا تجريبيًا يستخدم بيانات داخل المتصفح؛ لم تُربط بعد بواجهة API الجديدة.
- أُضيف أساس خادم محلي باستخدام Node.js وExpress وSQLite.
- يتضمن الخادم جلسات دخول، وتجزئة كلمات المرور باستخدام bcrypt، وحدًا لمحاولات تسجيل الدخول، وفحصًا للصلاحيات في الخادم.
- يتضمن مخطط SQLite للمستخدمين والشكاوى وسجل أحداث التدقيق، ونقاط API أولية لإنشاء الشكوى وعرضها وتغيير حالتها.
- لا تُزرع بيانات الشكاوى التجريبية القديمة في قاعدة البيانات تلقائيًا.

## المتطلبات والتشغيل المحلي

1. ثبّت Node.js إصدار 20 أو أحدث.
2. افتح مجلد المشروع في الطرفية.
3. انسخ `.env.example` إلى ملف باسم `.env`.
4. غيّر `SESSION_SECRET` إلى قيمة عشوائية طويلة، واضبط `ADMIN_USERNAME` و`ADMIN_PASSWORD` بكلمة مرور فريدة لا تقل عن 12 محرفًا.
5. نفّذ `npm install`.
6. نفّذ `npm test` لتشغيل الاختبارات.
7. نفّذ `npm start` ثم افتح `http://127.0.0.1:3000`.

عند أول تشغيل تُنشأ قاعدة البيانات في `data/complaints.sqlite` ويُنشأ حساب المدير الأول من متغيرات البيئة. إذا كانت قاعدة البيانات موجودة مسبقًا فلن تُستبدل كلمات المرور أو الحسابات تلقائيًا بتغيير ملف البيئة.

## واجهات API المتاحة في هذه المرحلة

- `GET /api/health`: فحص حالة الخدمة.
- `POST /api/auth/login` و`POST /api/auth/logout`: تسجيل الدخول والخروج.
- `GET /api/auth/me`: معلومات الجلسة الحالية.
- `GET /api/complaints`: عرض الشكاوى للمستخدم المسجل.
- `POST /api/complaints`: إنشاء شكوى بعد التحقق من الحقول.
- `PATCH /api/complaints/:id/status`: تحديث حالة الشكوى.
- `GET /api/audit`: قراءة أحدث أحداث التدقيق للمدير أو المراجع.

## حدود الأمان

هذا أساس تطوير محلي وليس نظامًا إنتاجيًا معتمدًا. لا تستخدم بيانات مواطنين حقيقية حتى يكتمل ربط الواجهة، وتُختبر إدارة المستخدمين والصلاحيات، والنسخ الاحتياطي والاستعادة، وسياسات الاحتفاظ، وحماية الجلسات وCSRF، ومراجعة أمنية مستقلة. سجل التدقيق محفوظ في قاعدة البيانات المحلية؛ مالك الجهاز أو من يملك صلاحية تعديل ملف SQLite يستطيع العبث به، لذلك لا يوصف بأنه غير قابل للتلاعب. لا تفعّل الوصول من الشبكة المحلية قبل إعداد جدار ناري وTLS ومراجعة إعدادات الأمان.

ملف `.env` وقاعدة البيانات المحلية مستثنيان من Git عبر `.gitignore`. لا ترفع أسرارًا أو قواعد بيانات حقيقية إلى المستودع.
