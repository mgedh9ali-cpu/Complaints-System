# قبول إعادة تصميم الواجهة — PR #57 (مدمج في main) (مدموج في main)

## نطاق التغيير المنفذ

- إعادة تصميم الألوان والأزرار والقائمة الجانبية والنوافذ والجداول، مع دعم RTL والخط المحلي والوضع الداكن.
- فصل الملف الضخم `app.full.js` إلى 15 ملفاً تحت `ui/` تجمعها `lib/ui-bundle.js`.
- تحويل تفاصيل الشكوى إلى صفحة مستقلة داخل التطبيق `#complaint/<id>` مع عرض البيانات والمعالجة والردود والإحالات والمرفقات والملاحظات والتسلسل الزمني.
- حفظ إنشاء الشكاوى وتغيير الحالات والردود عبر API مع CSRF؛ اعتماد الرد مع فصل المدير عن المؤلف، وبحفظ مؤكد قبل إظهار رسالة النجاح.
- لم يتغير مخطط SQLite ولا المسارات العامة لـAPI ولا منطق الصلاحيات على الخادم.

## اختبارات آلية أُضيفت

- `tests/app-bundle-regression.test.cjs`: وجود المصادر وترتيبها واكتمال تجميعها وصحة صياغتها.
- `tests/ui-browser-smoke.test.cjs`: محاكاة DOM لتنقل الصفحات السبع، وصفحة التفاصيل والرجوع، وإنشاء شكوى، وتغيير الحالة، وCSRF، واعتماد الرد، ورفض الأدوار غير المصرح لها.
- `tests/redesign-shell.test.cjs`: الحفاظ على معرفات التنقل والإجراءات وإمكانية الوصول.
- `tests/security-regressions.test.cjs`: رفض تقديم الملفات المصدرية `ui/` خارج المسار الآمن.
- تبقى اختبارات الوحدة والتكامل الموجودة للشكاوى والمرفقات والنسخ والمزامنة والاعتمادات.

هذه اختبارات في الكود، ولا تُعد نتيجة ناجحة حتى تنتهي وظائف GitHub Actions على آخر SHA، ولا تستبدل اختبار متصفح حقيقي.

## التحقق اليدوي الإلزامي قبل اعتماد التشغيل

1. بناء `npm run check` و`npm test` دون إخفاق، ثم تشغيل نسخة Windows Portable من نفس SHA.
2. تسجيل الدخول كـ admin، ثم staff ثم reviewer. تَحقق من إخفاء/منع أزرار الإنشاء والاعتماد والتعديل وفق الصلاحية.
3. المرور على كل قسم: لوحة العمل، سجل الشكاوى، الإحالات، الردود، الإشعارات، التقارير، الإعدادات.
4. إنشاء شكوى تجريبية وتعبئة البيانات وإرفاق ملفين، ثم التحقق من ظهور الرقم والملفات بعد إعادة تشغيل البرنامج.
5. فتح صفحة الشكوى من السجل، استخدام روابط أقسامها، إجراء انتقال حالة مسموح وآخر ممنوع، والرجوع إلى الصفحة السابقة.
6. إضافة ملاحظة، إحالة، وصياغة رد باستخدام حساب موظف، ثم اعتماد الرد من حساب مدير مختلف، وتوثيق الإرسال فقط بعد الاعتماد.
7. طلب حفظين متنافسين والتحقق من رسالة `409` وعدم فقد آخر تعديل مخزن.
8. تنزيل تقرير Excel وCSV، والتحقق من ضوابط منع حقن الصيغ، ثم تنزيل نسخة `.csb` مشفّرة واستعادة المرفقات منها على نسخة تجريبية.
9. اختبار الإشعارات، الوضع الداكن، الطباعة، لوحة المفاتيح، البحث `Ctrl+K`، وفتح القائمة وإغلاقها على الشاشة الصغيرة.
10. فحص التخطيطات على Windows عند 1366×768 و1024×768، ثم عرض ضيق (390px) بلا تداخل أزرار أو قص بيانات.
11. قياس فتح الصفحة والحفظ مع 100 شكوى اختبارية وعدم ظهور أخطاء في DevTools أو تسريب مصدر/ملفات SQLite عبر HTTP.
12. لا يُنشر البرنامج ببيانات مواطنين حقيقية قبل اعتماد الجهة لسياسات الحسابات، الحفظ، النسخ، والاستعادة.

## حالة الاعتماد

لا يمكن تأكيد نجاح اختبارات Windows أو التفاعلات في متصفح حقيقي من مراجعة الشيفرة فقط. دُمج طلب المراجعة #57 في `main`، لكن **اعتماد النسخة للإطلاق معلق** حتى نجاح اختبارات CI ومراجعة نسخة Windows Portable وبيانات التشغيل.
