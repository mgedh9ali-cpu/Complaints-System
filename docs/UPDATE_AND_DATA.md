# تحديث Windows وحفظ البيانات

الإصدار: **1.0.0-rc.9**. ثبّت ملف `complaints-system-1.0.0-rc.9-setup.exe` أول مرة لتفعيل آلية التحديث الجديدة. لا تستطيع الإصدارات القديمة التي تفتح صفحة GitHub تنزيل هذه الآلية تلقائيًا قبل تثبيتها.

## التحديث من داخل البرنامج

1. سجّل الدخول، ثم اضغط **تنزيل أحدث إصدار** من الإعدادات.
2. يظهر شريط التنزيل ونسبته ورقم الإصدار وملاحظاته. تُقبل حزمة المثبّت المنشورة في المستودع المعتمد فقط، مع مطابقة الحجم وبصمة SHA-256 التي يعرضها GitHub.
3. يحفظ البرنامج التغييرات المعلّقة، ويأخذ نسخة احتياطية كاملة عبر خدمة النسخ الحالية قبل التثبيت. فشل التحقق أو النسخ الاحتياطي يمنع التثبيت ويُبقي التطبيق الحالي.
4. يغلق البرنامج بعد تجهيز المثبّت، ويظهر شريط تثبيت Windows الفعلي. يستبدل المثبّت ملفات التطبيق في مسار التثبيت نفسه ويحدّث الاختصارات، ثم يعيد فتح البرنامج تلقائيًا.
5. بعد نجاح تشغيل الخادم وفحص قاعدة البيانات وسجل التدقيق وتحميل الصفحة، تُعرض رسالة نجاح تحتوي رقم الإصدار وما الجديد فيه. تُربط هذه الرسالة بمعرّف بناء GitHub، حتى لا يؤكد برنامج قديم يحمل الرقم نفسه نجاح تحديث أحدث.

يتطلب الاتصال بالإنترنت، وWindows x64، وصلاحية الكتابة في مسار التثبيت. لا يبدأ تحديث لمجرد نشر إصدار؛ يبدأ بالضغط على زر التحديث.

## المستودع الخاص

المستودع الحالي خاص. في أول تحديث يُطلب رمز وصول GitHub مرة واحدة:

- أنشئ **Fine-grained personal access token** من إعدادات GitHub، وحدد المستودع `mgedh9ali-cpu/Complaints-System` وحده، بصلاحية **Contents: Read-only**.
- أدخله في نافذة التحديث. يُحفظ مشفرًا بواسطة حماية Windows عبر Electron `safeStorage`؛ لا يوضع داخل الكود أو قاعدة الشكاوى أو سجلات التدقيق.
- عند انتهاء صلاحيته، يطلب البرنامج رمزًا جديدًا. إغلاق نافذة الإعداد يلغي العملية.
- يُرسل الرمز إلى API المستودع المعتمد فقط. لا يُرسل إلى رابط تخزين الملف بعد إعادة التوجيه.

لا يوفر ربط GitHub في ChatGPT تلقائيًا صلاحية وصول لتطبيق Windows على جهازك.

## البيانات والنسخة السابقة

قاعدة البيانات والمرفقات والإعدادات ومفاتيح التشفير وملف الحساب المحلي تبقى في `%APPDATA%\complaints-local-system`، بما في ذلك ملف البيانات المستعاد النشط. لا تُنقل إلى حزمة التطبيق ولا تُعاد تهيئتها أثناء التحديث. يحتفظ المثبّت بهوية التطبيق نفسها ولا يمسح بياناته عند الاستبدال.

النسخة المحمولة تنتقل إلى النسخة المثبتة. يُسجل ملفها الأصلي المعروف `complaints-system-*-portable.exe` وبصمته؛ لا يُحذف إلا بعد نجاح تشغيل البناء الجديد، وإذا بقي محتواه مطابقًا ولم يكن هو الملف الجاري. إذا كان الملف مقفلًا، تُعاد محاولة التنظيف في التشغيل التالي. النسخ المحمولة التي أُعيدت تسميتها وملفات التنزيل التي نسخها المستخدم يدويًا لا تُحذف بالبحث في جهازه.

تُحذف حزمة التنزيل المؤقتة بعد نجاح التشغيل؛ تعذّر تنظيف ملف مقفل لا يوقف التطبيق. لا يُحذف مجلد البيانات أو النسخ الاحتياطية. إذا تعثّر التثبيت، يمكن إعادة فتح التطبيق السابق والمحاولة مجددًا؛ النسخة الاحتياطية السابقة للتحديث تبقى في مجلد النسخ المعتمد. لا توجد استعادة آلية لإصدار التطبيق إذا فشل مثبت Windows بعد بدء الاستبدال.

## التحقق والإصدار

يبني مسار Windows المثبّت بعد اختبارات المشروع، ويسجل SHA-256 والتزام المصدر. يُضمّن `desktop/build-info.json` داخل الحزمة لتأكيد هوية البناء عند التشغيل. بصمة GitHub عبر HTTPS ليست شهادة Authenticode؛ لا توجد شهادة جهة مرفقة بالمستودع.

ملاحظات ما الجديد تأتي من وصف إصدار GitHub، وتُعرض كنص دون تنفيذ HTML. يجب تحديث وصف الإصدار عند نشر تغييرات لاحقة ليعكس محتواه الفعلي.

اختبارات المنطق المعزول تشمل فشل البصمة والتنزيل الجزئي والنسخ الاحتياطي وصلاحية المدير وإطلاق المثبّت، وعزل رمز القراءة عن روابط التنزيل، ومنع تأكيد بناء قديم، والحفاظ على ملفات البيانات. يظل اختبار التحديث بين نسختين مثبتتين فعليًا على Windows مطلوبًا قبل اعتماد التشغيل العام.
