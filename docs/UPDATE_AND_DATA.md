# التنزيل كملف واحد + التحديث دون فقدان البيانات

## ماذا تريد؟

تطبيق مثل البرامج العادية:
1. تنزّل **ملفاً واحداً** من المتصفح
2. تضغط عليه فيعمل فوراً
3. عند صدور تحديث: تستبدل الملف فقط **وتبقى كل الشكاوى**

## كيف يتحقق ذلك؟

### 1) بناء النسخة المحمولة (مرة من جهاز المطوّر)

على جهاز فيه Node وWindows (أو بيئة بناء):

```bash
git pull
npm install
npm run dist:win
```

المخرج:

```text
dist-desktop/complaints-system-0.7.5-portable.exe
```

هذا **ملف واحد**. ارفعه في GitHub → Releases كمرفق للإصدار.

### 2) المستخدم النهائي

- يفتح صفحة الإصدارات في المستودع
- ينزّل الملف `.exe`
- يضغط مرتين → يفتح التطبيق (بدون فك مجلدات يدوياً)

> يحتاج وجود **Node.js** على الجهاز حالياً لأن الغلاف يشغّل خادم Node المحلي.
> النسخ المستقبلية يمكن تغليف Node داخل الحزمة إن رغبت.

### 3) أين تُحفظ بياناتك؟

**ليس داخل ملف الـ exe.**

المسار التقريبي على Windows:

```text
%APPDATA%\complaints-local-system\   (أو اسم المنتج في Electron)
  ├── .env                  إعدادات الدخول
  └── data\
        ├── complaints.sqlite   ← كل الشكاوى هنا
        ├── sessions\
        └── instance-id
```

لذلك:

| ماذا تفعل؟ | هل تروح البيانات؟ |
|------------|-------------------|
| استبدال ملف `.exe` بنسخة أحدث | **لا** |
| حذف مجلد `%APPDATA%\...` | **نعم** — هذا مسح متعمّد |
| نسخ احتياطي من داخل التطبيق | يحفظ نسخة من قاعدة البيانات |

### 4) دورة التحديث الموصى بها

```text
أنت (المطوّر)                المستخدم
─────────────────            ─────────────────
عدّل المستودع على GitHub
ابنِ portable exe
ارفع Release
                             ينزّل الملف الجديد
                             يستبدل القديم القديم (أو يشغّل الجديد)
                             البيانات تبقى في AppData
```

### 5) تشغيل من المجلد (بدون ملف واحد)

ما زال يعمل للمطوّرين:

```bash
npm install
npm run start:desktop
```

أو `start-desktop.bat` — هذا **ليس** ملف واحد للمستخدم النهائي؛ للمطور فقط.

## ملخص جملة واحدة

**البرنامج = ملف exe. البيانات = مجلد منفصل في AppData. حدّث البرنامج دون لمس مجلد البيانات.**
